# 人物記憶與提及格式

確認問題：模型輸出把 mention 放進 inline code；其他人的既有上下文會帶入過長的私有資料，且沒有事件表的紀錄。

- 發送前針對已辨識的人物 ID、唯一別名與 mention 做正規化；程式碼及網址不改寫。
- 人物別名依伺服器保存，改名保留；歧義名稱不猜測。紀錄明確提到人物的陳述，附評論者、訊息 ID、時間與來源頻道，問句不當評論。
- 個人評論不等於事實，不從稱呼推導人格、犯罪或敏感屬性。敏感個資與指令內容不保存至人物評論表。
- 事件取既有標記表，限制為當前頻道且提問者可讀歷史。評論查詢同樣限制當前伺服器與當前頻道，私訊不向其他人分享。
- 以人物上下文取代直接讀取其他人的完整私有對話；重要人物資訊另置於最後，避免長上下文裁切。
- 提供擁有者及當事人查詢／清除人物評論的指令；測試、部署與推送。
