# 店家搜尋時效

問題：一般網頁摘要缺少店家狀態、日期與分店資料，模型可能用過時食記推薦已停業店家。

實作：沿用 SerpApi 帳戶，對餐飲／營業時間類查詢改用 google_maps engine；一般問題仍用 google，明確最新／近期查詢使用近月日期篩選。店家不假設使用者位置，沿用問題提供的地點。

- 保存 Maps 營業狀態、分店地址、每週時間、電話與來源連結；永久／暫停營業明確標為排除，保留證據供回答解釋；今日打烊不能當倒閉。
- Maps 要求 no_cache=true，本機成功結果快取兩分鐘；一般結果保留十分鐘。閉店結果不視為搜尋失敗，避免自動換回舊食記。
- 普通網頁保存來源日期；未提供日期／超過一年前的年份提示時效限制，不能宣稱營業已確認。
- 模型提示要求核對同分店、資料衝突與官方公告，狀態未確認時只列待核實候選，不能湊數。
- 測試：正常營業／今日休息／永久及暫停、全閉店不備援、日期與一般問題不走 Maps；一次真實查詢取得五筆結構化店家，仍不保證所有狀態即時正確。
